# Lost & Found AI Matcher — Evaluation Procedure (Phase 5)

This directory defines how the image-similarity matcher is measured.
**Rule: no accuracy percentage may be quoted anywhere unless it was produced
by an actual run of this procedure against a concrete, committed dataset.**

## 1. Dataset layout

```
evaluation/
  lost_found_dataset/
    gallery/            # items "already in the system"
      <label>/          # one folder per distinct physical item
        img_01.jpg
        img_02.jpg
    queries/            # new photographs a student would report
      <label>/          # SAME label as the matching gallery folder
        img_01.jpg
    metadata.csv        # OPTIONAL (see §3)
    evaluation_report.md  # generated by the runner
```

A *label* identifies one unique physical object (e.g. `casio-fx991-black`).
Every query must have at least one gallery image with the same label, and
gallery folders should contain images of *different* objects of the same
category to act as realistic distractors.

## 2. Capturing real campus test photographs

1. Photograph 20–30 distinct common campus items (calculators, bottles, ID
   wallets, chargers, books, keys, umbrellas …).
2. For each item take **3–5 gallery photos** (different angle, distance,
   lighting: daylight corridor / canteen / library desk) and **1–2 query
   photos** that look like a typical hurried user upload.
3. Keep distractors present: photos of *other* items go into their own label
   folders — never into the same folder.
4. Copy everything into the layout of §1 and run:

```
python evaluate_matcher.py
```

## 3. Optional `metadata.csv`

Allows the full-composite (image + context) mode to use realistic report text:

```csv
path,report_type,title,category,color_hint,location_reported,description,date
gallery/casio-fx991-black/img_01.jpg,found,Found Casio calculator,Electronics,Black,Central Library,Black scientific calculator with yellow sticker,2026-10-01
queries/casio-fx991-black/img_01.jpg,lost,My calculator,Electronics,Black,Library reading hall,Black casio fx-991 with sticker,2026-10-02
```

Run the composite mode with `--full-composite`; image-only mode is the default.

## 4. What is measured

| Metric | Meaning |
|---|---|
| Precision@1 | share of queries whose #1 ranked gallery image shares the label |
| Hit@3 / Hit@5 | a correctly labeled image appears in the top 3 / 5 |
| MRR | mean reciprocal rank of the first correct label |
| Threshold sweep | Precision@1 restricted to queries whose top score passes each composite threshold — used to tune `LF_MATCH_MIN_COMPOSITE` / `LF_STRONG_MATCH_SCORE` |

The generated `evaluation_report.md` contains the per-query outcomes so any
failure can be inspected and fed back into preprocessing/weight tuning.

## 5. Synthetic smoke test

`python evaluate_matcher.py --generate-synthetic` creates deterministic
shape/colour fixtures so the *procedure itself* is always runnable and
testable. Those numbers characterize the synthetic set ONLY and must never be
presented as real-campus accuracy.

## 6. Tuning loop

1. Measure → 2. inspect worst per-query outcomes in the report →
3. adjust (in order): dataset hygiene, thresholds in `.env`
   (`LF_MATCH_MIN_COMPOSITE`, `LF_STRONG_MATCH_SCORE`, `LF_MEDIUM_MATCH_SCORE`,
   `LF_DUPLICATE_SCORE`), then matcher weights in `app/utils/image_matcher.py` →
4. re-measure. Every release should ship the last measured report.
